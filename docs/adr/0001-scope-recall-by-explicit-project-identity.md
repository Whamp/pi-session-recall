# Scope recall by explicit project identity before ranking

Conversation Recall defaults ordinary searches to project scope now that Git repositories and exact non-Git session origins have deterministic identities. Personal project lineage extends admission by mapping absolute historical session-origin roots to canonical repository identities. Bounded quality evidence still gates the production index rebuild; it does not leave the tool contract on a transitional global default.

Project scope admits candidates by exact project identity inside dense, lexical, and identifier retrieval before each channel limit. Canonical Git origins join equivalent clones; a repository's real shared Git directory joins its worktrees when no usable origin exists. An existing non-Git directory uses its exact session origin, so parent, descendant, nearby, and similarly named paths remain separate. Configured lineage takes precedence over Git discovery for an exact root and its descendants, including deleted historical roots. Overlaps across target identities fail configuration instead of inventing precedence. Ranking, deduplication, reranking, and context expansion run unchanged on the admitted candidates.

The index manifest records the lineage policy identity and a digest of normalized declarations. A lineage change requires an explicit rebuild so every stored row receives attribution from one coherent policy.

Production indexing also requires clean version-4 bounded evidence. That evidence binds the default project-scope policy, project identity and lineage policy versions, fixture lineage digest, hybrid rank-fusion constants, 512/64 chunk geometry, eight candidates per channel, and five final results. The fixed corpus materializes its declared Git checkouts, worktree, and clones beneath the guarded evaluation directory and checks their expected identities through the production resolver before indexing. It measures project and global latency separately and proves all three retrieval channels filter before their limits. The rollout gate requires complete measurements and bounded-work counters, recomputes the selected policy from the frozen thresholds, and rejects pre-scope, partial, inconsistent, or stale-policy evidence.

We rejected path-name similarity, content inference, automatic fallback, mixed scopes, environment or repository-local lineage settings, project graphs, and document path-reference machinery. Those alternatives blur the stated boundary or add unmeasured admission rules. Global search remains the explicit escape hatch, and an empty project search recommends that explicit retry without broadening automatically.
