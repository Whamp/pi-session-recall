# Scope recall by explicit project identity before ranking

Conversation Recall defaults ordinary searches to project scope now that Git repositories and exact non-Git session origins have deterministic identities. Configured lineage extends project admission separately. Bounded quality evidence still gates the production index rebuild; it does not leave the tool contract on a transitional global default.

Project scope admits candidates by exact project identity inside dense, lexical, and identifier retrieval before each channel limit. Canonical Git origins join equivalent clones; a repository's real shared Git directory joins its worktrees when no usable origin exists. An existing non-Git directory uses its exact session origin, so parent, descendant, nearby, and similarly named paths remain separate. Ranking, deduplication, reranking, and context expansion run unchanged on the admitted candidates.

We rejected path-name similarity, content inference, automatic fallback, mixed scopes, and document path-reference machinery. Those alternatives blur the stated boundary or add unmeasured admission rules. Global search remains the explicit escape hatch, and an empty project search recommends that explicit retry without broadening automatically.
